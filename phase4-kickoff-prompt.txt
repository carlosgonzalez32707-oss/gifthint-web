(Amazon Associates + Skimlinks), group gift platform fees (Stripe), and a

1. lib/affiliate.ts is SERVER-ONLY PERMANENTLY.
   Chrome Web Store Policy §4.4 prohibits affiliate rewriting in extensions.
   The same applies to any client bundle, mobile app, or shared package.
   lib/affiliate.ts must NEVER enter packages/shared/.
   The mobile Share Extension calls POST /api/v1/save; the server applies rewriting.

2. The existing /api/* routes must not break.
   The web app and Chrome extension depend on them.
   Phase 4 mobile routes go under /api/v1/* as thin wrappers — they call the same
   handlers. Do not modify existing route signatures.

3. Two Stripe webhooks, two secrets.
   /api/group-gift/webhook  uses STRIPE_WEBHOOK_SECRET
   /api/billing/webhook     uses STRIPE_BILLING_WEBHOOK_SECRET
   Never mix them up. Each is a separate endpoint in the Stripe Dashboard.

4. React Native has no cookie jar.
   The Supabase client in the mobile app must use:
     auth.storage: AsyncStorage
     auth.detectSessionInUrl: false
   Do NOT use supabase-browser.ts (which uses js-cookie) in the mobile app.

5. isPro() and hasFeature() for all feature gating.
   Never check subscription_status directly in UI or API code.
   lib/permissions.ts handles both the paid subscription and referral unlock paths.

6. RLS on every new table.
   ALTER TABLE <table> ENABLE ROW LEVEL SECURITY;
   Service-role-only tables: no public policies (the silence IS the policy).
   Document intent with a comment block.

7. Fail open on infrastructure.
   Rate limiting, Redis, price checking, and push notification delivery all fail open.
   Never block a real user action due to a third-party service outage.

8. No PII in error responses.
   serverError() in lib/api-response.ts logs raw errors server-side and returns
   a generic message to the client. Never include user emails, names, or IDs in
   4xx/5xx JSON responses.

MOBILE APP — GOOGLE AUTH PATTERN
───────────────────────────────────────────────────────────────────────────────

apps/mobile/lib/auth.ts:

  import * as WebBrowser from 'expo-web-browser'
  import { supabase } from './supabase'

  WebBrowser.maybeCompleteAuthSession()

  export async function signInWithGoogle() {
    const { data, error } = await supabase.auth.signInWithOAuth({
      provider: 'google',
      options: {
        redirectTo: 'gifthint://auth/callback',
        skipBrowserRedirect: true,
      },
    })
    if (error || !data.url) throw error ?? new Error('No auth URL')

    const result = await WebBrowser.openAuthSessionAsync(
      data.url,
      'gifthint://auth/callback',
    )

    if (result.type === 'success') {
      const { data: session } = await supabase.auth.getSession()
      return session
    }
  }

Note: this does NOT call /api/auth/exchange — that endpoint is extension-only.
The mobile app completes OAuth natively via Expo AuthSession.

───────────────────────────────────────────────────────────────────────────────

apps/mobile/lib/api.ts:

  import { supabase } from './supabase'

  const API_BASE = process.env.EXPO_PUBLIC_API_URL!  // https://gifthint.io

  export async function apiFetch<T>(
    path: string,
    options?: RequestInit,
  ): Promise<T> {
    const { data: { session } } = await supabase.auth.getSession()
    const headers: HeadersInit = {
      'Content-Type': 'application/json',
      ...(session ? { Authorization: `Bearer ${session.access_token}` } : {}),
      ...options?.headers,
    }
    const res = await fetch(`${API_BASE}${path}`, { ...options, headers })
    const json = await res.json()
    if (!res.ok) throw new Error(json.error?.message ?? 'API error')
    return json.data as T
  }
